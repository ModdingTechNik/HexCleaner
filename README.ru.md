# HexCleaner

[English](README.md) | **Русский** | [Українська](README.uk.md)

Очистка мусорных файлов и кэшей Windows. Написана на Rust, интерфейс на [egui](https://github.com/emilk/egui).

Программа удаляет только кэши, временные файлы, журналы и отчёты об ошибках.
Документы, сохранения игр, а также cookies, пароли и историю браузеров она не трогает.
Корзина очищается, только если отдельно отмечен пункт «Очистка корзины» (по умолчанию он выключен).

**Скачать:** [последний релиз](https://github.com/ModdingTechNik/HexCleaner/releases/latest) ·
**Поддержать проект:** [Patreon](https://patreon.com/ModdingTechNik)

## Сборка

```bash
cargo build --release
```

Получаются две программы:

* `target/release/HexCleaner.exe` — окно;
* `target/release/HexCleanerCli.exe` — командная строка (для скриптов и планировщика Windows).

Обе работают на одном ядре и с одними настройками.

## Как это работает

* Пункты со значком щита требуют прав администратора. Без прав они неактивны и при очистке
  пропускаются, но галочки на них запоминаются. Кнопка «Запустить от администратора»
  перезапускает программу через UAC.
* У каждого пункта есть уровень безопасности — цветная точка в списке:
  🟢 «Безопасно» (временные файлы и кэши, всё пересоздаётся само),
  🟡 «Умеренно» (что-то придётся скачать заново или пропадут данные для диагностики),
  🔴 «Осторожно» (журналы событий, история Защитника, файлы для восстановления программ).
* Наборы галочек: встроенные «Только безопасное», «Рекомендуемый» (безопасное и умеренное)
  и «Полный» строятся по уровням безопасности. Текущий выбор можно сохранить как свой набор
  и потом применять или удалять. Пункты, которые ещё ни разу не трогали, отмечены
  по рекомендуемому набору.
* Кнопка «Анализ» ничего не удаляет и не меняет: обходит те же папки по тем же правилам
  и показывает, сколько мусора найдено в каждом пункте. Пункт можно раскрыть
  и увидеть папки с объёмом и числом файлов (клик по папке открывает её в проводнике).
  Итоги анализа пишутся в отчёт `analysis_….log`. Если после анализа начать очистку,
  внизу окна видна полоса прогресса: сколько файлов из найденных уже удалено.
* Выбор пунктов, свои наборы и всё, что настраивается во вкладке «Настройки», хранится
  в `%APPDATA%\HexCleaner\settings.json`. При первом запуске язык берётся из настроек Windows.
* Каждая очистка пишет журнал в `%LOCALAPPDATA%\HexCleaner\logs`: в него попадают все
  удалённые файлы с размерами, ошибки и итоги по каждому пункту. Если в настройках стоит
  галочка «Сжимать прошлые журналы» (включена по умолчанию), перед новой очисткой журналы
  прошлых очисток сжимаются: в zip-архивы (по одному на журнал, по умолчанию) или сжатием NTFS
  папки журналов (журналы остаются обычными текстовыми файлами).
* Занятые файлы пропускаются. Временные файлы моложе часа не удаляются.
* Перед очисткой программа проверяет через Restart Manager, не держат ли файлы выбранных пунктов
  запущенные браузеры или лаунчеры (Steam, Epic), и предлагает их закрыть — с галочками
  и возможностью запустить снова после очистки. Закрываются они корректно, как при выходе
  из Windows (браузеры сохраняют вкладки), ничего не завершается принудительно.
  Предлагаются только программы из списка `programs_to_close` пункта: общие папки
  (кэш шейдеров видеокарты, `INetCache`) держат и посторонние программы, и компоненты Windows.
* Для каждого файла, который не удалось удалить, журнал называет причину: например,
  «занят процессом chrome.exe (PID 1234)», «запущен или загружен как библиотека»,
  «нет прав, владелец NT SERVICE\TrustedInstaller». Процессы-блокировщики ищутся через
  Restart Manager не больше 200 раз за пункт, чтобы не замедлять очистку.
* Символические ссылки и точки соединения (junction) не открываются, поэтому через них
  невозможно добраться до чужих файлов. Корни дисков, профиль пользователя, Windows,
  Program Files и подобные папки защищены от очистки, даже если в каталоге окажется ошибка.

## Корзина

Файлы пунктов очистки можно не удалять, а переносить в собственную корзину HexCleaner. Каждая
очистка получает свою папку, в которой повторяется полный путь файла, а вместо диска — папка
с его буквой: `C:\Windows\Temp\a.tmp` → `Trash\2026-10-28 14-03-12\c\Windows\Temp\a.tmp`.
Рядом `2026-10-28 14-03-12.json` описывает, какой пункт какой файл перенёс. Папка по умолчанию —
`%LOCALAPPDATA%\HexCleaner\Trash`; саму папку корзины очистка не трогает, даже внутри очищаемой.

* Для каждого пункта выбирается, что делать с его файлами: «В корзину в пределах лимита»
  (по умолчанию), «Всегда в корзину» или «Удалять сразу» — в настройках или правым щелчком
  по пункту. Память, журналы событий и корзина Windows очищаются средствами системы, без корзины.
* После очистки у каждого пункта, перенёсшего файлы в корзину, есть кнопка с круговой стрелкой
  против часовой — она возвращает их. С зажатым Shift кнопка «Начать очистку» становится красной
  «Удалить навсегда» со значком предупреждения: такая очистка идёт мимо корзины. Новый анализ или очистка сбрасывает эти кнопки; после этого
  (или после перезапуска) всё можно вернуть на вкладке «Корзина»: очистку целиком, пункт, папку
  или отдельные файлы. Файлы, на месте которых уже есть новые, остаются в корзине.
* Если файлы не помещаются в лимит, очистка останавливается и спрашивает: освободить место
  (удалить из корзины самые старые очистки), игнорировать лимит, удалить без корзины или
  остановить очистку. Командная строка (и плановая очистка) спросить не может — не поместившееся
  удаляется.
* Настройки: ползунок размера корзины и рядом точное число гигабайт (крайнее левое — отключена,
  крайнее правое — без ограничений, по умолчанию 5 ГБ), срок хранения очисток в днях (более
  старые удаляются при запуске программы и перед каждой очисткой; по умолчанию выключен), сжатие (NTFS — файлы сжимает файловая система; ZIP — каждая
  очистка упаковывается в `<очистка>.zip` с той же структурой) и папка корзины.

## Место на диске

Вкладка «Место на диске» показывает, что занимает место на диске или в папке. Выберите диск
(в списке видно свободное место), папку в стандартном окне Windows или введите путь.
Папка сканируется в фоне (в несколько потоков; сканирование можно остановить), затем её содержимое
показывается от больших элементов к меньшим: папки — с размером всего, что внутри, и числом
файлов, и файлы. Щелчок по папке открывает её; «Вверх» и путь по частям возвращают назад,
а подъём выше просканированной папки сканирует родительскую. В меню по правому щелчку есть и
«Удалить в корзину»; с зажатым Shift пункт превращается в «Удалить навсегда» со значком
предупреждения. Корни дисков, Windows, Program Files, профиль пользователя и саму корзину там
удалить нельзя. «← Назад» и «Вперёд →» (и боковые
кнопки мыши) ходят по истории открытых папок. Правый щелчок по строке — показать
в проводнике или скопировать путь.

Рядом со списком — кольцевая диаграмма открытой папки. Элементы меньше 3 % объединены в сектор
«Остальное»; щелчок по нему раскрывает его в отдельную диаграмму («← Назад» возвращает),
щелчок по сектору папки открывает папку. Символические ссылки и точки соединения не открываются,
поэтому ничего не считается дважды.

В результатах анализа на вкладке «Очистка» щелчок по папке предлагает открыть её
в «Место на диске» или в проводнике.


На вкладке «Настройки» можно добавить пункт «Анализ папки в HexCleaner» в контекстное меню
проводника для папок, фона открытой папки и дисков — всегда или только при щелчке правой кнопкой
с Shift. Он записывается в `HKCU\Software\Classes` (права администратора не нужны) и запускает
`HexCleaner.exe --disk-space "<папка>"` — окно открывается на вкладке «Место на диске».
В Windows 11 пункт — в «Показать дополнительные параметры». Если программу перенесли, при
следующем запуске пункт переписывается на новое место.

## Командная строка

```bash
HexCleanerCli analyze --preset recommended --details
```

```bash
HexCleanerCli clean --preset safe --tasks recycle_bin --quiet
```

| Команда | Что делает |
|---|---|
| `analyze [что] [параметры]` | Анализ: сколько мусора найдено. Ничего не удаляет |
| `clean [что] [параметры]` | Очистка |
| `list` | Пункты (идентификаторы, уровень безопасности, отмечены ли в программе) и наборы |
| `config [show \| get \| set \| reset]` | Настройки программы (см. ниже) |
| `trash [list \| show \| restore \| delete \| empty]` | Корзина HexCleaner (см. ниже) |
| `help` | Справка с примерами |

Что обработать — всё указанное складывается:

* `--preset <имя>` — `safe`, `recommended`, `full` или название своего набора;
* `--tasks <id,id,...>` — отдельные пункты (идентификаторы из `list`);
* `--exclude <id,id,...>` — убрать пункты из выбранного;
* `--selected` — пункты, отмеченные в окне программы. Если ничего не указано, берутся они же.

Параметры: `--details` (папки с мусором), `--quiet` (только итог), `--lang <код>`,
`--compress-logs` / `--no-compress-logs`, `--close-apps` (перед очисткой закрыть мешающие
браузеры и лаунчеры; при анализе — только показать их), `--restart-apps` (после очистки
запустить закрытые программы снова), `--no-trash` (удалять сразу, мимо корзины — как очистка
с Shift в окне).

Очистка из командной строки, как и в окне, переносит файлы в корзину HexCleaner (если она
включена) по тем же лимиту и правилам пунктов. Спросить, что делать при переполнении, некого,
поэтому не поместившиеся файлы удаляются мимо корзины — это отмечается в журнале. В итоге
пишется, сколько перенесено и в какую папку; вернуть файлы можно командой `trash` или в окне
на вкладке «Корзина».

### Корзина: `trash`

То же, что вкладка «Корзина» окна:

```bash
HexCleanerCli trash
```

```bash
HexCleanerCli trash restore latest --tasks browsers_cache
```

* `trash` (или `trash list`) — очистки в корзине, новые первыми, с номерами;
* `trash show <очистка> [--files]` — пункты очистки с идентификаторами (и файлы);
* `trash restore <очистка>` — вернуть файлы на место. `--tasks <id,...>` — только эти пункты,
  `--path <путь>` — только файлы из этой папки или этот файл (можно указать несколько раз).
  Файлы, на месте которых уже есть новые, остаются в корзине (код возврата 2);
* `trash delete <очистка> --yes` — удалить очистку из корзины навсегда;
* `trash empty --yes` — удалить из корзины всё. Без `--yes` удаление не выполняется.

`<очистка>` — номер из списка (1 — самая новая), `latest` или имя, например `2026-10-29 10-56-42`
(кавычки не обязательны). Очистки старше срока хранения удаляются, как при запуске окна.

### Настройки: `config`

Те же настройки, что на вкладке «Настройки» окна:

```bash
HexCleanerCli config
```

```bash
HexCleanerCli config set trash.limit 10GB
```

```bash
HexCleanerCli config set trash.policy.browsers_cache never
```

* `config` (или `config show`) — все настройки: ключ, значение, пояснение и допустимые значения;
* `config get <ключ>` — одно значение (удобно в сценариях);
* `config set <ключ> <значение>` или `config set <ключ>=<значение>`;
* `config reset <ключ> [<ключ> …]` — вернуть как по умолчанию.

| Ключ | Значения |
|---|---|
| `language` | код языка (`ru`, `uk`, `en` или свой файл перевода) или `system` |
| `theme` | `dark`, `light`, `system` |
| `notify`, `flash_taskbar` | `on`, `off` |
| `logs.compress` / `logs.compression` | `on`, `off` / `ntfs`, `zip` |
| `trash.limit` | `5GB`, `500MB`, `1.5GB` (число без единиц — ГБ), `off` — отключена, `unlimited` |
| `trash.keep_days` | 1–3650 или `off` |
| `trash.compress` / `trash.compression` | `on`, `off` / `ntfs`, `zip` |
| `trash.path` | папка или `default` |
| `trash.policy.<id>` | `normal`, `always`, `never` — для пунктов, удаляющих файлы |
| `explorer_menu` | `on`, `shift` (только с Shift), `off` — пункт открывает `HexCleaner.exe` из той же папки |
| `updates.check_on_start` | `on`, `off` |

Окно читает настройки при запуске: если оно открыто, перезапустите его — иначе при следующем
сохранении оно запишет поверх свои.

Пункты, которым нужны права администратора, без этих прав пропускаются — для них
командную строку (или задание планировщика) нужно запускать от имени администратора.
Ctrl+C останавливает работу аккуратно: службы запускаются обратно, журнал дописывается.

Коды возврата (их показывает планировщик Windows):

| Код | Значение |
|---|---|
| 0 | Готово без ошибок |
| 1 | Ошибка в параметрах |
| 2 | Готово, но часть файлов не удалось удалить или часть пунктов пропущена |
| 3 | Не удалось начать (например, создать журнал) |
| 4 | Остановлено по Ctrl+C |

## Плановая очистка

Вкладка «Плановая очистка» создаёт задания в Планировщике заданий Windows (папка
`\HexCleaner\`): что очищать (набор или отмеченные пункты), когда (ежедневно, по дням
недели или в число месяца) и в какое время, закрывать ли мешающие программы, удалять ли
файлы сразу, мимо корзины (`--no-trash`), и запускать ли с правами администратора (это можно выбрать, только если HexCleaner запущен от имени
администратора). Задания можно включать и выключать, менять, удалять и запускать сразу.

Задание запускает `HexCleaner.exe --scheduled clean --tasks … --quiet` — ту же команду, что
и `HexCleanerCli.exe`, но без окна и без мелькающей консоли; журнал пишется как обычно.
Так же можно запускать любые команды командной строки, даже если `HexCleanerCli.exe` нет:
`HexCleaner --scheduled help`. Кроме этого `HexCleaner.exe` принимает только `--disk-space <папка>`
(см. «Место на диске»): на другие параметры, как и
на `--help`, он показывает справку — в консоли, если запущен из неё, иначе в окне сообщения.
Программа регулярно сверяет свой список с Планировщиком: если задание удалили в
«Планировщике заданий», оно помечается в списке, и его можно создать снова или убрать.
Задания HexCleaner в Планировщике, которых нет в списке, показываются отдельно.

## Настройки и обновления

Вкладка «Настройки»: язык и тема (тёмная, светлая или как в Windows); уведомление
по окончании анализа или очистки и мигание кнопки на панели задач (каждое можно отключить);
сжатие прошлых журналов; обновления; ссылки на релизы GitHub и на Patreon.

При запуске окно спрашивает у GitHub последний релиз
(`api.github.com/repos/ModdingTechNik/HexCleaner/releases/latest`; черновики
и pre-release туда не попадают). Если его тег новее версии программы, появляется диалог:
«Обновить», «Напомнить через день / 3 дня / неделю», «Пропустить эту версию» (о следующей
программа напомнит) или «Не проверять обновления» (включается снова в настройках).
Там же — «Проверить сейчас»: ручная проверка предлагает и пропущенную версию.
При запуске GitHub спрашивается не чаще раза в 5 минут (время последней проверки хранится
в настройках, `updates.last_check`); кнопка «Проверить сейчас» работает всегда.

Версии сравниваются по правилам SemVer с любым числом частей: `0.10.0` новее `0.9.1`,
`0.1` и `0.1.0.0` — одна версия, `0.2.0-beta.1` старше `0.2.0`. Программа сообщает,
если установленная версия новее последнего релиза (например, собрана до его выпуска),
если опубликованных релизов нет (есть только черновики или pre-release) и если тег
последнего релиза — не номер версии.

Обновление: загружается zip-архив релиза, сверяется с SHA-256, которую считает GitHub,
и распаковывается рядом с программой. Работающий exe переименовывается в
`*.update-old` (удаляется при следующем запуске), новый встаёт на его место, программа
перезапускается. Путь не меняется, поэтому задания Планировщика продолжают работать.
Если в папку программы нельзя писать (например, `Program Files`), HexCleaner попросит
запустить его от имени администратора. Сеть — через WinHTTP, встроенный в Windows
(системный прокси и сертификаты), без сторонних библиотек.

Как выпустить обновление:

1. Поднимите `version` в `Cargo.toml` (например, `0.2.0`).
2. Выполните `cargo dist`: он соберёт `cargo build --release` и упакует `HexCleaner.exe` и
   `HexCleanerCli.exe` в `target/release/release.zip`, проверит архив и покажет его SHA-256.
   Сжатие — Deflate через Zopfli (меньше минуты): обычный zip, но меньше, чем у zlib на
   максимуме. Другие методы (LZMA и т. п.) обновление не распакует. Можно упаковать и вручную:
   нужен zip с этими двумя файлами со сжатием Deflate или без сжатия, имя любое.
3. Создайте релиз на GitHub с тегом, равным версии (`0.2.0` или `v0.2.0`), приложите архив.
   Описание релиза программа покажет в диалоге как «Что нового». Релиз с галочкой
   «Set as a pre-release» программа не предлагает — так можно выложить тестовую сборку.

## Языки

Все тексты программы (интерфейс, журналы, причины ошибок) лежат в файлах перевода,
в коде их нет — только ключи вида `t!("footer.analyze")`. Встроенные языки — русский,
украинский и английский (`languages/ru.json`, `languages/uk.json`, `languages/en.json`) —
вшиты в программу. При первом запуске язык берётся из настроек Windows.

При запуске программа выкладывает их в папку `%APPDATA%\HexCleaner\languages`
(кнопка «Папка языков…» во вкладке «Настройки»). Чтобы добавить свой язык:

1. Скопируйте `en.json`, например, в `de.json` — имя файла станет кодом языка.
2. Поменяйте `name` (так язык называется в списке) и переведите тексты в `strings`.
   Подстановки в фигурных скобках (`{files}`, `{size}` …) оставьте как есть.
3. Откройте список языков — новый язык появится в нём.

Непереведённые ключи берутся из английского, так что перевод можно делать постепенно.
Файл `ru.json` или `en.json` в этой папке дополняет встроенный язык: в нём достаточно
оставить только те тексты, которые хочется поменять. Удалённый файл встроенного языка
будет создан заново при следующем запуске.

Тесты проверяют, что у всех ключей из кода есть перевод, что в словарях нет лишних ключей
и что в коде не осталось непереведённых русских строк.

## Темы

Цвета окна тоже лежат в JSON-файлах — так же, как переводы. Встроенные темы — тёмная
и светлая (`themes/dark.json`, `themes/light.json`) — вшиты в программу и при запуске
выкладываются в папку `%APPDATA%\HexCleaner\themes` (кнопка «Папка тем…» во вкладке
«Настройки»). В них перечислены все цвета, которые можно задать. Чтобы добавить свою тему,
положите в эту папку, например, `ocean.json` — имя файла станет кодом темы:

```json
{
  "name": { "ru": "Океан", "uk": "Океан", "en": "Ocean" },
  "base": "light",
  "colors": { "accent": "#0077BE", "link": "#0077BE", "background": "#EEF5FA" }
}
```

* `name` — название в списке: строкой или по кодам языков (берётся язык программы, затем
  английский). Без него в списке будет имя файла.
* `base` — `dark` или `light`: цвета, которых нет в `colors`, берутся из этой темы.
* `colors` — цвета `#RRGGBB` или с прозрачностью `#RRGGBBAA`; `chart` — список цветов секторов.

| Цвет | Где виден |
|---|---|
| `background`, `window`, `window_border` | Фон окна; диалоги, списки, подсказки и их рамка |
| `input`, `stripe` | Поля ввода и полосы прогресса; полосы через строку в таблицах |
| `text`, `text_weak` | Обычный текст; пояснения |
| `border` | Разделители и рамки групп |
| `button`, `button_text` | Кнопки, флажки, ползунки и их текст |
| `button_hovered`, `button_hovered_text`, `button_hovered_border` | То же под мышью |
| `button_pressed`, `button_pressed_text`, `button_open` | Нажатые; раскрытый список |
| `accent`, `accent_text` | Выделение: выбранный пункт, заполнение ползунка, выделенный текст |
| `link`, `warning`, `error` | Ссылки, предупреждения, ошибки |
| `success`, `found`, `failure` | Итоги очистки и анализа, ошибки очистки, точки уровня безопасности, кнопка «Удалить навсегда» |
| `chart` (список), `chart_rest` | Секторы диаграммы на вкладке «Место на диске» и сектор «Остальное» |

Новая тема появится в списке, как только его откроете; правки в файле видны, если выбрать
тему заново. Файл `dark.json` или `light.json` в этой папке дополняет встроенную тему:
достаточно оставить в нём только те цвета, которые хочется поменять. «Как в системе»
переключает встроенные тёмную и светлую по настройке Windows. Непонятые цвета и ошибки
в файле показываются в настройках, а тему можно выбрать и из командной строки:
`HexCleanerCli config set theme ocean`.

### Добавление пункта

В `all_tasks()` в `src/catalog.rs` добавьте ещё один `CleanupTask`:

```rust
CleanupTask {
    id: "my_app_cache",                       // по нему запоминается галочка
    safety: Safety::Safe,                     // уровень безопасности: Safe, Moderate или Caution
    programs_to_close: &[],                   // программы, которые можно предложить закрыть
    requires_admin: false,
    services_to_stop: &[],
    actions: vec![
        clear_dir(r"%LOCALAPPDATA%\MyApp\Cache"),          // очистить содержимое папки
        delete_files(r"%LOCALAPPDATA%\MyApp\*.log"),       // удалить файлы по маске
    ],
},
```

Заголовок и описание пункта добавьте в `languages/ru.json`, `languages/uk.json`
и `languages/en.json` с ключами `task.my_app_cache.title` и `task.my_app_cache.description`.

В путях можно использовать переменные окружения (`%LOCALAPPDATA%`, `%WINDIR%` …),
специальную переменную `%STEAM%` (папка Steam из реестра) и маску `*`.
